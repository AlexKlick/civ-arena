# Scouting feedback from completed turns

This change addresses a confirmed strategic-productivity gap in the observed prefix of `minimax60-20260905T052156Z`. P0 submitted the same adjacent destination for turns 1–5 with unchanged projected coordinates; P1 moved on turn 2, then repeated a different unchanged destination for turns 3–5. Movement allowance changed from zero to two, which previously appeared only as generic observation change. Subsequent own-turn origins confirmed no net displacement at those observations. The evidence does not identify the underlying engine reason.

The retained audit is `runs/60-round-live-20260905T052156Z/scouting-audit.md` in the main reliability worktree, alongside its immutable event prefix and machine-readable observations. This isolated patch does not change that live run or convert operational turn completion into strategic-success evidence.

The controller now remembers an accepted move whose immediate projected coordinate is unchanged, but only after its issuing turn closes successfully. At the next consecutive own turn, it checks the already refreshed projected unit list. A changed coordinate or missing/non-owned unit clears the history. An unchanged origin confirms an observed non-progress episode and temporarily removes that destination from automatic candidate selection for three own turns. A turn-1 attempt confirmed on turn 2 is excluded on turns 2, 3 and 4; it is eligible again on turn 5. This is a heuristic cooldown, not a declaration that the engine considers the move illegal.

The existing seeded heuristic re-ranks the remaining candidates. Current tactical overrides retain priority, including an explicit move to a temporarily excluded destination. When no automatic candidate remains, the existing safe hold applies. The system never immediately retries an accepted potentially pending move, invents positive movement, or changes restore/refreeze ownership. Spent movement and the explicitly trusted frozen-opening roster still govern attempts. Model cadence, request caps, provider configuration and strict turn closure remain unchanged.

Memory is private to each fresh-only controller and bounded to sixteen owned units and six adjacent destinations per unit. Records use deterministic engine-turn counters; no wall clock or additional engine/model query is involved. At capacity, this turn's sorted pending-action roster takes priority, followed by older cooldown records in sorted unit-ID order. Resume remains unsupported because this memory, like the current directive state, is not checkpoint-restored.

Each scouting graph records confirmations, forgotten attempts, expiry and exact active exclusions. Individual move records preserve generic `observation_changed`/`outcome` compatibility and add `position_changed`, `destination_observed`, `movement_allowance_changed` and `movement_outcome`. Missing post-action ownership leaves position/movement comparisons unavailable rather than inventing a coordinate. A movement allowance change alone is `submitted_displacement_unconfirmed`. Successful closure records list pending next-turn confirmations; a failed closure does not commit them.

Further cases cover rejection, delayed arrival, loss/ownership change, gaps, exact cooldown expiry, overrides, exhausted candidates, spent movement, deterministic ordering and bounded storage. No live-engine efficacy or calibrated strategic-strength claim follows from these tests.
