## How it's implemented
- Tool loop: `LLMAgentRuntime.take_turn` (src/civ_arena/agents/llm/runtime.py:128-220) sends one user turn-header, then up to `llm.max_tool_rounds` (16, configs/live-hotseat-llm-minimax2-001.yaml:28; default config.py:50) requests. Assistant content is echoed back verbatim, thinking included (runtime.py:172); tool results go in one user message (runtime.py:214). A reply with no tool_use force-closes the turn (runtime.py:176-179); round-cap exhaustion also force-closes (runtime.py:215-217), with one bounded fortify pass to satisfy the unmoved-units completeness gate (runtime.py:230-241). Conversation is discarded at end of turn (runtime.py:13-15).
- Client wire: `MiniMaxMessagesClient` speaks the Anthropic Messages shape (src/civ_arena/agents/llm/client.py:1-11,182-188); retries on 429/502/503/504 with `0.5*2**attempt` backoff (client.py:36,322-347); EVERY attempt increments `posts_sent` (client.py:305) and fires `on_post`/`on_attempt`. Budget is double-checked: runtime pre-request (runtime.py:243-250) and client per-attempt (client.py:138-143,298) against `max_requests_per_match` (2000, config.py:54); either trip or any `ModelUnavailable` ends the match via `MatchAborted` (runtime.py:218-220).
- System prompt: identity-free doctrine "You are the leader of a civilization… matched against another civilization" with an Observe→Act→Remember→Finish liturgy and "Be decisive" (src/civ_arena/agents/llm/prompts.py:15-61); curated variant for paced turns (prompts.py:76-105).
- Facade: the manifest is 20 tools, not 15 (src/civ_arena/agents/llm/tool_schemas.py:13-294; registry src/civ_arena/session/tools.py:163-184). In paced/curated mode the 7 BASIC_READS are stripped and `inspect_context` added (runtime.py:251-258; `BASIC_READS` at src/civ_arena/agents/llm/context_curator.py:12-13). Dispatch is kwargs-only through the closure-bound `ToolFacade` (runtime.py:316, session/tools.py:187-219); unknown names/malformed args become error tool_results with fixed keys `llm_unknown_tool`/`llm_malformed_args`, no repair re-prompt (runtime.py:268-310). Tool results compacted/truncated to `max_result_chars` 8000 (runtime.py:341-348).
- Memory: per-turn `write_diary` (2000-char cap, last-write-wins, src/civ_arena/arena/diary.py:16-29) rebuilt on resume from events.jsonl TOOL_CALL/TOOL_RESULT pairs (diary.py:32-62); typed strategy store via `set_goal`/`record_prediction`/`record_lesson` (session/tools.py:135-154) scored MET/MISSED/SELF_ASSESS on metric (cities/units/techs/gold/population) at deadline (src/civ_arena/strategy/scoring.py:31-85); `recall_lessons` is cross-match corpus retrieval, honestly rejected when no corpus is configured (src/civ_arena/arena/referee.py:457-470; wiring coordinator.py:103-107). Both feed the next turn's header through `render_memory`, a 2400-char budgeted view with fixed caps and drop ladder (src/civ_arena/strategy/view.py:17-28,169-221; header at prompts.py:64-73).
- strategic_autopilot: the factory binds a `StrategicController` (src/civ_arena/agents/runtime.py:84-91); `take_turn` delegates wholesale (runtime.py:134-136). The model makes exactly one forced `submit_directive` call (`tool_choice` pinned, src/civ_arena/agents/llm/strategic_controller.py:642-645) with max two attempts (one format repair) (strategic_controller.py:620-628,704-736); everything else — scouting graph, growth/settlement/initial-capital, research and per-city production (≤32 cities, strategic_controller.py:757-758) — is deterministic execution of the directive (strategic_controller.py:385-875). Decisions trigger on 5-turn cadence, city-roster/contact/settler/research/loss/damage deltas (strategic_controller.py:224-246); quiet turns re-execute the last directive with zero requests (strategic_controller.py:347-348).

## What it optimizes
- Legacy prompt objective is vibes: "Be decisive. Observe, act, keep your goals and diary current, end your turn" (prompts.py:60-61) — no score components, no win condition, no reward shaping anywhere in `SYSTEM_PROMPT`. Curated prompt adds operational hygiene (batching, don't repeat deduped requests, "Model-reported confidence is not calibrated probability") but still no objective (prompts.py:76-105).
- The only explicit optimization pressure is self-authored: goals with deadline+metric get auto-verdicts, predictions get scored, and the rendered header shows REVIEW DUE verdicts ("MISSED (gold=150)") plus lessons (view.py:62-109), nudging the model toward commitments it will be graded on. The strategic controller's SYSTEM optimizes procedural compliance (unit targets, two SCOUTs, one BUILDER/city, defender counts, recovery holds) rather than any arena score (strategic_controller.py:47-144).

## Expected failure modes
- Budget exhaustion: round cap force-close mid-plan (runtime.py:215-217); `max_requests_per_match` trip is match-ending (runtime.py:245-250, client.py:139-143). Curated mode raises `MatchAborted` on any result exceeding the context budget instead of truncating (runtime.py:344-345).
- Tool rejection loops: prompt normalizes rejections as noise (prompts.py:54-56), but nothing detects a repeat-offender loop — a model re-issuing an illegal move burns rounds until the cap; identical accepted actions dedupe, and the curated prompt warns repeats are swallowed (prompts.py:85).
- Prompt-driven rigidity: legacy prose hard-codes a 1v1 frame ("matched against another civilization", prompts.py:17) and a fixed 4-step liturgy; end_turn completeness rejection is scripted to cost exactly one extra round-trip.
- Memory bloat: diary capped at 2000 chars, memory view at 2400 with caps (4 goals, 6 review items, 3 lessons) — bloat is structurally impossible but stale sightings and self-assess claims accumulate up to those caps (view.py:17-23).
- Wire failures: 429/5xx retried (max 2) with backoff, all counted; unretryable 4xx, malformed JSON-in-200, transport errors, and missing env key all become `ModelUnavailable` → `MatchAborted` with a redacted 300-char snippet (client.py:322-357).
- decision_mode: legacy degrades per turn (force-close, match continues); strategic aborts the WHOLE match on any model failure, directive rejection after repair, capital-unresolved, or no-eligible-production (strategic_controller.py:452-457,725-728,822-829), is fresh-only (resume forbidden, strategic_controller.py:253-256, coordinator.py:171-172), and poisons itself after first failure. Adaptive context adds count_tokens failures as aborts (strategic_controller.py:544-569).

## Observable signatures
- summary.json `telemetry` per agent: `tool_calls`, `tool_errors`, `model_errors`, `total_calls`, `total_errors`, `total_ms`, `input_tokens`, `output_tokens`, `model` (src/civ_arena/arena/telemetry.py:41-52; written at coordinator.py:234-250). Legacy llm shows many tool_calls/turn and `model_errors` keys like `llm_malformed_args`; strategic shows near-zero calls, near-zero errors, occasional `strategy_failed`-era aborts.
- `llm_costs.jsonl`: one row per counted POST attempt with ts/kind/attempt/status_code/latency/tokens/payload_hash plus join keys `decision_id`, `logical_request_id`, `request_set_key`, `turn`, `match_id`, `run_id` (src/civ_arena/agents/llm/wire_log.py:28-75; wired at src/civ_arena/game/civ6/live_driver.py:92-135).
- `spend.jsonl`: one bare `{agent_id, player_id}` line per attempt, fsync'd, survives checkpoint rewind (src/civ_arena/arena/spend.py:23-29; coordinator.py:107,143).
- events.jsonl: TOOL_CALL/TOOL_RESULT pairs (diary rebuild depends on them, diary.py:38-57); strategic audits arrive as HEARTBEAT envelopes with `strategy_payload_json` — kinds `strategy_request`, `strategy_response_shape`, `strategy_decision`, `decision_boundary`, `strategy_execution`, `strategy_graph`, `strategy_economy`, `strategy_failed` (strategic_controller.py:155-209; src/civ_arena/agents/runtime.py:130-136).

## Variance sensitivity
- Seat position: none by design — prompts and memory view are identity-free (prompts.py:3-8), seat only changes what the facade returns; profile seed is checkpointed but never drawn (runtime.py:22-23).
- Map seed: no direct model sensitivity, but terrain/choke layout drives exploration rounds and visible-entity volume, hence tokens.
- Opponent count (2 vs 4): legacy cost scales superlinearly — `get_units`/`get_cities`/`get_visible_map` grow with contacts and own expansion, each result truncated at 8000 chars (runtime.py:341-348), and within a turn input tokens compound because verbatim assistant turns plus all tool results accumulate in `messages` (runtime.py:172,214). More units → more completeness rejections → more rounds. The legacy SYSTEM_PROMPT explicitly assumes a bilateral duel (prompts.py:17) while tool descriptions say "rivals" plural (tool_schemas.py:18) — in a 4-seat field the prose under-describes the threat model. Strategic mode is flatter: one decision request whose context is rendered under a budget (strategic_controller.py:638-641; provider-counted hard window when adaptive, 567-574) plus rare economy-refresh decisions, with a 32-city abort bound (757-758) as the only hard scale cliff; its trigger set (new contact, city change) fires more often with 3 rivals, raising request cadence but not per-request size.

Config note: `parse_config` now REJECTS `decision_mode: strategic_autopilot` at `player_count != 2` (Lane A). The legacy `llm` policy would PARSE at 4 seats (it is not bilateral in code, only in prompt prose) — a 4-seat LLM seat is mechanically runnable but the prompt's 1v1 frame under-describes the field; flag to the research loop before any 4-seat LLM batch.
