## How it's implemented
- Per turn: observe (overview/units/cities/map via `EntityBoundary`) → fold into `PlannerBelief` → determinize `bstate = SimState.from_doc(build_state_doc(belief, seed=turn))` → if `needs_choice` (no active option, terminated, no longer initiated, or `turn - chosen_at_turn >= RESELECT_EVERY=3`) run `search_option` → compile the active option's step → guarded execute → end turn (src/civ_arena/planner/runtime.py:490-565, constants at runtime.py:105-112: `SEARCH_METHOD="mcts"`, `SEARCH_BUDGET=12`, `EPOCH_TURNS=3`, `RESELECT_EVERY=3`, `PROPOSER_POST_CAP=64`).
- Option menu: 8 hand-authored options — expand, develop, defend, rush, scout_frontier, tech_race, economy, fortify_line — each an `Option(initiation, termination, compile_step)` (src/civ_arena/planner/options.py:309-349). Steps emit only `legal_actions` output (options.py:1-9); compilers are greedy per-turn heuristics (e.g. `_expand_step` options.py:167-183, `_rush_step` options.py:223-238, sight-bounded `_move_toward` options.py:85-107).
- MCGS vs MCTS: identical except the depth-2 node key — `f"path:{oid1}"` for mcts vs the canonical `abstract_key(world, pid)` for mcgs, so convergent option sequences share visit/value stats (src/civ_arena/planner/search.py:4-10, 249-256). Default flipped to `mcts` per an M16 gate ruling (runtime.py:100-105).
- Rollout: determinize belief fresh per rollout (`seed*10_007+i+1`, search.py:244), simulate epoch 1 (3 turns) under the depth-1 option, pick depth-2 option by UCT (`UCT_C=140.0`, search.py:37, 168-186), simulate epoch 2, score leaf with `value_of` (search.py:243-264). Simulated turns run `run_ambient` + compiled option steps for self (check-then-apply, search.py:121-125) and `run_ambient` + `stock_ai_turn` for every opponent (search.py:139-148); mid-epoch terminated options fall back to `tech_race` filler (search.py:135-140); foreign-unit confidence decays inside the rollout (search.py:150-156). `stock_ai_turn` moves each unit one legal step and queues WARRIORs — never founds cities, never sets research (src/civ_arena/game/sim/engine.py:172-201).
- Optional LLM ranking prior: `proposer.py` renders a compact belief view + menu with live `available_now` booleans (proposer.py:66-119); the model returns JSON `{"ranked": [...], assumptions, contingencies}`; `compile_proposal` narrows to legal-now known ids (proposer.py:122-151). Any failure (ModelUnavailable, malformed text, budget) degrades to no prior (runtime.py:187-210). Case-base prior: signature = projection of the same abstract doc (drops `turn` + per-player `development`), ranked by mean differential among takens via exact integer cross-multiplication (src/civ_arena/planner/casebase.py:49-75, 197-229). Bandit prior: 6-axis integer context (own cities/gold-ladder/researched-ladder/units-ladder, strongest-rival cities/researched-ladder), per-(context,option) `n`/`adv_sum`, advantage = `value_of(now) - value_of(prev decision world)`, ≤512 contexts with smallest-n eviction (src/civ_arena/planner/bandit.py:87-124, 251-306; runtime.py:253-279, 518-543).
- Priors only permute FIRST-VISIT order under the untried-first rule; merge order proposer → case → bandit, first occurrence wins (runtime.py:115-141, 507-523; search.py:168-186, 198-207). Choice = max root visits, then total value, then id (search.py:266-268).
- Option → actions: `OPTIONS[active].compile_step(bstate, pid)` → sim-to-real vocabulary filter (substitute wire-offered tech/production ids, drop dead ones) → `execute_plan` prevalidates each action on a rolling belief state, applies deterministic tools, reconciles (re-observe + retire dead attack targets) on attack/purchase, cascades failures (runtime.py:554-556, 329-374; src/civ_arena/planner/executor.py:37-117). `unmoved_units` bounce → fortify + re-end (runtime.py:561-565). End-of-turn belief/option/bandit state journals to `runs/<id>/planner/p<n>-journal.jsonl` (runtime.py:567-590; src/civ_arena/arena/coordinator.py:152-156).

## What it optimizes
- Leaf objective `value_of = own scalarized score − strongest rival's` (src/civ_arena/game/sim/value.py:62-71); weights `cities=100, population=20, techs=30, units=10, gold=1` (value.py:18-24). Optional M20c `weights` dict threads verbatim into the leaf only (runtime.py:73-80; search.py:220-228). Match measurement uses the same objective over summary scores (`score_differential`, value.py:45-59; scripts/league.py:269-270; scripts/strategy_benchmark.py:182).
- Bias: city count dominates (100/pop) — found-a-settler lines win rollouts; gold is near-worthless (1) so hoarding/buy decisions are tiebreakers only; military is cheap tempo (units=10) and killing a rival unit only moves the differential by 10. Menu bias: `expand` disappears at ≥3 cities (options.py:311-313) — no 4+-city strategy; `economy`/`fortify_line` never self-terminate (options.py:341-348), relying on the 3-turn reselect cadence; `develop` ends when all 3 buildings exist (options.py:303-306); `defend` reacts only within radius 4 (initiation) / 6 (termination) with confidence-gated threats (options.py:318-321; src/civ_arena/planner/uncertainty.py:34-35).

## Expected failure modes
- Search budget: 12 rollouts vs up to 8 candidates — the first 8 rollouts are one visit each (untried-first), leaving ~4 refinements; near-tied values make `chosen` a coin flip on visit counts; horizon is only 6 turns (2 epochs × 3), so any payoff beyond ~2 epochs (multi-epoch tech beelines, long marches) is invisible; the depth-2 value credits both root and child the same leaf (search.py:262-264).
- Opponent model: rollouts imagine `stock_ai_turn` rivals that never found cities or research (engine.py:194-200) — real expansionist/planner rivals grow far faster, so `value_of` at the leaf overstates own dominance and undervalues defensive/tech options; the deterministic 3-turn reselection also means rollout epochs assume uninterrupted execution.
- Belief model: own science_bucket prior 0 (under-predicts research completion), foreign gold prior 100, foreign cities rebuilt with empty queues/hp 100 (belief.py:24-41, 361-370); no-expiry ghosts are suppressed only when contradicted by live observation (belief.py:318-324). At >2 players: see Variance sensitivity — several assumptions break outright.
- Option-menu blind spots: no diplomacy/coalition concept, no 4th-city expansion, no naval/district play, rush terminates on units-only because the sim has no city capture (options.py:324-330) — military can never conquer, only farm `units` score.
- LLM prior unavailable (the default in every league/benchmark arm — scripts/strategy_benchmark.py:206-208 arms `proposer=None, case_base=None, bandit=None, weights=None`): `_prior_order` falls back to canonical (alphabetical) candidate order (search.py:204-207), so at budget < candidate count the *alphabet* decides what gets explored — `defend`/`develop`/`economy` before `rush`/`tech_race`. A dead proposer also flips bandit credit assignment off (advantage updates only happen at armed needs_choice turns).

## Observable signatures
- `runs/<id>/planner/p0-trace.json` / `p1-trace.json` (league.py:255-258) or `planner-p<n>-trace.json` (strategy_benchmark.py:234-236): one entry per decision with `method, chosen, candidates, root_key, seed, budget, epoch_turns, prior, root_visits, root_values, rollouts, nodes_expanded, unique_states, transposition_hits` plus optional `proposal`/`case_prior`/`bandit_prior` blocks (runtime.py:545-552; search.py:57-69). Fingerprints: `chosen` cycling in ~3-turn blocks (`RESELECT_EVERY`); `root_visits` concentrated 3-4 on one option with the rest at 1; `transposition_hits>0` only under `mcgs`; `proposal.error == "model_unavailable"` or `proposer_budget_exhausted` when the prior died (runtime.py:197, 204).
- `runs/<id>/events.jsonl` kinds: `MATCH_START`, `LEASE_GRANT`/`LEASE_RELEASE` per (turn, pid), `TURN_END`, `TOOL_RESULT` with `status=rejected` counted per seat as the dirtiness gate, `VIOLATION`, `MATCH_END` carrying the summary (league.py:247-251; strategy_benchmark.py:150-185).
- Score over time: per-turn `root_key` embeds each player's abstract doc (cities/population/gold_bucket/researched/units) — parseable as the score trajectory (search.py:89-112); end-state differential from `summary.json` via `score_differential`; `planner_work` per run records decisions/nodes_expanded/budget (strategy_benchmark.py:237-241).

## Variance sensitivity
- Seat: deterministic in `(player_id, seed)` but seats get fixed distinct RNG seeds (SEAT_SEEDS 7/22, league.py:81, 239-240), so each seat determinizes different unknown-terrain draws; league treats the two seatings of one map seed as one inferential cluster precisely to absorb seat asymmetry (league.py:21-27, 294-312).
- Map seed: unknown tiles are sampled from `_weighted_terrain` per rollout (belief.py:283-294; layouts.py:28-35) — terrain mix shifts founding targets (`_found_targets` options.py:149-161) and growth pacing; small seed samples → wide variance in whether `expand` beats `tech_race`.
- 2 vs 4 seats — concrete bilateral assumptions:
  - `duel_start` refused non-2 counts (now parameterized by Lane A) and the adapter hardcoded `_player_count = 2` (simulator.py — now threaded from config).
  - belief.py:51 imports `STARTS`; the unseen-rival prior does `STARTS.get(opid)` and `continue`s on `None` (belief.py:384-404). At 4 seats, rivals 2/3 materialize with zero units and zero cities until first sight → `value_of`'s rival term collapses, rollouts wildly overestimate dominance, and `rush` initiation (`_foreign_coords` empty) stays off; `START_ROSTER` itself is the duel roster (belief.py:69).
  - The belief world is a `MAP_RADIUS=5` hex re-centered on the player's own anchor (belief.py:151-170, 283-294; state.py:19) — on the radius-7 4-seat map, distant rivals' translated coordinates fall on tiles the doc never created, so their units/cities sit on nonexistent tiles and sim rules break or strand them; remembered terrain beyond radius 5 is unreachable.
  - `value_of`/`score_differential` are "own − max rival" (value.py:45-71): mechanically N-safe but strategically bilateral — no coalition/kingmaking term; weakening the weakest rival earns nothing while the strongest rival runs away.
  - `context_bucket` collapses all rivals into the single strongest rival's (cities, researched ladder) (bandit.py:100-124): 2 rivals' state is invisible to the bandit, and contexts proliferate toward the 512-context eviction bound (bandit.py:89-92).
  - `_simulate_epoch`'s opponent loop is generic (search.py:139-148) but gives every rival the same trivial `stock_ai_turn` — no per-rival modeling, no rival-vs-rival interaction in the imagination.
  - proposer `render_view` lists foreign units/cities without owner labels (capped at 6 units/4 cities, proposer.py:74-94): even at 2 seats the model cannot attribute threats to a specific rival; at 4 seats multi-front reasoning is structurally out of reach.

Config note: `parse_config` now REJECTS `policy: planner` at `player_count != 2` (Lane A) — the bilateral assumptions above are the reason.
